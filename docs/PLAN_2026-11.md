## How to read the estimates

- **Dev days**: focused days for one developer or agent, including tests and docs, excluding review waits.
  Ranges are low-high; the high end covers the surprises typical for that kind of work.
- **Owner**: the owner's hands-on time (device runs, accounts, decisions). External waits (Google verification,
  store review) are listed separately because they are calendar time, not work.
- **Where it is proven**:
  - **Sandbox**: fully buildable and testable in this Linux environment (JVM/Android unit tests, fakes, simulated
    peripherals). Most Kotlin, including iOS-side logic placed in `commonMain`.
  - **Sandbox + device**: code and tests here, then one confirmation on a real phone/recorder by the owner.
  - **Mac**: needs macOS/Xcode (Swift, Apple cinterop, iOS simulator, macOS native audio). Kotlin for iOS in
    `core`/`ai`/`ble` can be compile-checked here; `composeApp` iOS and running iOS tests cannot.
  - **Owner**: accounts, payments, legal, product decisions.

Rule for iOS and macOS work: keep the logic in common Kotlin with thin platform adapters, so almost all of it is
tested here before the Mac build.

## Recommended order (traction first)

Android phone recording, import, local/API AI, templates and AutoFlow already work without any Plaud device. The
fastest way to get users is to **ship that as a public beta now**, with Plaud support labelled experimental until the
hardware validation passes, and to add features people share (Omi support, Notion/Slack, a macOS meeting recorder).

| Phase | Duration (1 dev) | Content | Dev days |
|---|---|---|---|
| 1. Public Android beta | 2-3.5 weeks | Signed APK on GitHub Releases + IzzyOnDroid, Play internal track (#26), website live with polished shots (#23, #24, #25), one review round (#107) | 10-17 |
| 2. Traction features, no owner dependency | 2-4 weeks | Omi driver (#15) + DIY Friend devices (#16), Notion export (#59), Slack post via webhook URL (#61) | 11-19 |
| 3. Plaud path (after owner's device runs) | 2.5-4.5 weeks | Owner validations #3-#9; Wi-Fi fast path wired into the app (#8) + close-race fix (#357); test APK (#11) | 12-23 |
| 4. macOS meeting recorder | 5-7.5 weeks | D1 mic + system audio (#30), D2 local STT (#31), MCP/CLI over notes (#34 part), D4 packaging (#33) | 25-38 |
| Later | - | Google/Microsoft integrations, P2P sync, iOS, desktop meeting detection, cloud | see tables |

Start these **owner actions now** because their lead time is long: Google Cloud project + OAuth verification (weeks),
Play developer account, Apple developer account (iOS + macOS notarization), a domain for the site, and the device
identity extraction (#3).
