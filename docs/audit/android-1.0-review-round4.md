# Android 1.0 review, round 4

**Date:** 2026-11-03
**Revision reviewed:** `61859d5484980989ffb5614cdd7e11e1967a1fb9` (`origin/main`, merge of #309)
**Scope:** Android app and shared modules: `plaud-protocol`, `ble`, `core`, `ai`, `recorder`, `composeApp` (androidMain + commonMain). iOS, desktop and website were not reviewed.
**Method:** Fresh whole-app code read with no trust in rounds 1 to 3. Product invariants (BLE opcode and settings guards, no cloud/telemetry/account paths, no personal values in logs) were checked directly. Privacy/security, threading/data loss, and i18n/a11y/test coverage were read in three parallel passes; every finding below was re-checked by hand against the code at the revision above. Scoped JVM tests were run for `plaud-protocol` and `ble` (see Gates).

---

## Verdict

**No p0.** Nine p1 findings, mostly on the import path (cache-only storage, quadratic decode, crash on provider errors, truncated watched-folder copies), plus plaintext speaker embeddings that survive a wipe, two AutoFlow bugs, a pt-BR title default, and opcode 30 not being guarded on the way out. The BLE forbidden-opcode and forbidden-setting guards are sound and tested.

## Checked and found clean

- **Forbidden opcodes 5, 104, 128, 0xFE20, 143 and settings 4, 26:** single choke point `GuardedLink` runs `PlaudWriteGuard` on a defensive copy of the plaintext before sealing; handles `[0x01, cmd u16]`, trimmed `[0x01, cmd]` and bare unlock frames; cmd 8 rejects settings 4/26 for reads and writes (value-0 trim case covered). `Framing.encodeCommand` also refuses forbidden opcodes. `GattWrite` constructors are `internal`; `GattArchitectureTest` bans raw writes outside `:ble`. Omi and Pocket profiles declare no writable characteristic. Tests: `GuardedLinkTest`, `PlaudDeviceClientTest`, `OmiProfileTest`, `SimulatedPeripheralScenariosTest`. (Opcode 30 is the gap, see R4-09.)
- **Device-config writes:** Wi-Fi config opcodes 116/120-125 are defined but have no outbound caller.
- **No cloud, account or telemetry paths:** no Plaud API client (`PlaudDeviceClient` explicitly refuses FE10 generation via the cloud), no analytics/crash SDKs, `NoTelemetrySettingsTest` and `NoTelemetryUiStringsTest` present. Google Calendar OAuth exists in `core` but its client id comes from `System.getenv`, so on Android it is never configured and `IntegrationRegistry` omits it from the UI (dead code, not a visible placeholder).
- **Logging:** all `Log.*`/`println` in app modules log fixed text, counts or exception class names. No transcripts, titles, serials, bind tokens, MACs or keys found. WorkManager error output goes through `ApiErrorSanitizer`.
- **Manifest:** only `MainActivity` exported; services, receiver and FileProvider not exported; `allowBackup=false` with backup and data-extraction rules; network security config disallows cleartext except loopback; location capped at SDK 30 and scan `neverForLocation`.
- **FileProvider:** exposes only `cache/share/`; share intents grant read only.
- **Secrets:** API keys and device keys in Keystore-backed `SecureStore` (AES-GCM, random IV); API base URL and webhook URL require https except loopback; no hardcoded secrets found.
- **Download path:** `persistDownloadedSession` streams to an fsynced `.part` and renames atomically under a mutex; resumable partials are checkpointed and truncated to the checkpoint; cancellation is rethrown.
- **Mic FGS:** promotion before disk/AudioRecord work, stop/join off main, generation tokens against stale sessions.
- **Model downloads:** https only, sha256 pinned, verified before rename, staged extraction.
- **DB:** `insertRecording` is plain `INSERT`; recording/user-content ids use wide random space; chain migration test present.
- **i18n key parity:** EN and pt-BR string tables are data classes with named arguments, so missing keys fail compilation; Android `strings.xml` pairs have identical keys.
- **Test coverage on critical paths exists** for wipe, SecureStore key invalidation, BLE resume/CRC, migrations, id generation and AutoFlow. Gaps are listed per finding above.
